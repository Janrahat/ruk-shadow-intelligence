# Security architecture

## Authentication and sessions

- Passwords are hashed with **Argon2id** (`argon2-cffi`). A 10-character minimum
  and a common-password blocklist are enforced by
  `security.validate_password_strength()`.
- Password and CSRF comparisons are constant time (`hmac.compare_digest`).
- Session cookies are `HttpOnly`, `SameSite=Lax`, and `Secure` when HTTPS is on.
- Login is rate limited per address; failures increment a per-account counter.
- Login errors never reveal whether the username or the password was wrong, and
  neither value is echoed back into the page.

## Authorization

Every `/admin/*` route is wrapped in `@admin_required`, which redirects an
unauthenticated GET to the login page. `tests/test_routes.py` asserts this for
**every** admin route individually, including `/admin/api/stats`,
`/admin/export` and `/admin/stream`.

## CSRF

Every state-changing request requires a token that matches the session-stored
value: login, link create / revoke / restore / delete, campaign create, all four
privacy actions, and the visitor's consent submission. A missing or wrong token
returns `400` with **no** side effect. Each is tested.

The visitor consent form is covered too, so a third-party page cannot silently
submit a consent decision on a visitor's behalf.

## Injection

### SQL

Every value is a bound parameter. The only interpolated identifiers are table
names drawn from a fixed literal list and a `GROUP BY` column checked against an
allow-list (`ALLOWED_BREAKDOWN_COLUMNS` in `analytics.py`). A table-dropping
payload in a search field is asserted to be treated as a literal, with the tables
still present afterwards.

### XSS

Jinja2 autoescaping is on for every template, and the CSP forbids inline script.
A `<script>` tag in a campaign name is asserted to be escaped in the rendered
consent page and dashboard.

### CSV formula injection

Exports are generated by the server from stored values. Visitor-supplied text is
sanitised at the boundary, so a leading `=` cannot arrive from a visitor.

## SSRF and open redirects

`security.validate_destination_url()` runs before any link is created and
rejects:

- schemes other than `http` / `https` (script, data, file, ftp, gopher, vbscript)
- embedded credentials (`https://user:pass@host`)
- loopback: `127.0.0.0/8`, `::1`
- private ranges: `10/8`, `172.16/12`, `192.168/16`, `fc00::/7`
- link-local and cloud metadata: `169.254.0.0/16` (including
  `169.254.169.254`), `fe80::/10`
- unspecified and reserved addresses: `0.0.0.0`, documentation ranges
- the blocked hostnames `localhost`, `metadata`, `instance-data` and the
  `.local`, `.internal`, `.lan`, `.corp`, `.test`, `.invalid` namespaces
- bare hostnames with no dot
- whitespace, CR/LF, backslashes and control characters anywhere in the URL
- URLs longer than 2048 characters
- public hostnames whose **DNS answer** is any address in the ranges above

That last check is the one that matters: it blocks the classic trick of a public
name whose A record points at `127.0.0.1`. Unresolvable hostnames are refused
explicitly rather than silently allowed.

Redirects after consent always go to the stored, already-validated destination -
never to a value supplied in the request. `safe_redirect_target()` restricts
post-login redirects to same-origin relative paths.

## Security headers

Sent on every response:

```
Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self';
                         img-src 'self' data:; connect-src 'self'; font-src 'self';
                         object-src 'none'; frame-ancestors 'none';
                         base-uri 'self'; form-action 'self'
X-Content-Type-Options: nosniff
X-Frame-Options: DENY
Referrer-Policy: no-referrer
Permissions-Policy: geolocation=(), camera=(), microphone=(), payment=(), usb=()
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Resource-Policy: same-origin
Strict-Transport-Security: max-age=31536000; includeSubDomains   (HTTPS only)
```

The public surface gets a **stricter** policy than the admin surface:
`script-src 'none'`, `style-src 'self'`, `connect-src 'none'`. The consent page
needs no JavaScript at all, so it is not granted any.

## Rate limiting

Sliding-window limiter, in-process, keyed by **session token or address** -
never by visitor identity, so rate limiting cannot become a tracking mechanism.

| Scope | Default |
|---|---|
| Login attempts | 8 per 5 minutes per address |
| Public link hits | 120 per minute per address |
| Consent submissions | 120 per minute per address |

> **Limitation.** The limiter holds state in process memory. Behind multiple
> worker processes each worker keeps its own counter, so the effective limit is
> `limit x workers`. For a single-process Waitress deployment this is exact.
> Use a reverse-proxy limiter if you scale out.

## Proxy headers

`X-Forwarded-For` is only honoured when `TRUST_PROXY_HEADERS=true`, and only if
the left-most entry parses as an IP address. Leaving it false prevents a visitor
from spoofing their own address and poisoning the analytics.

## Secrets

- No secret is hardcoded anywhere. `SECRET_KEY` comes from the environment.
- In development a missing key is generated into `.ruk_secret` with mode `0600`;
  in production a missing or short key is a **startup failure**.
- A test greps the terminal module for hardcoded secret, password and token
  literals and fails if one appears.
- `.gitignore` excludes `.env`, `.ruk_secret`, `*.pem`, `*.key` and the database.
- `install.sh` generates a 64-hex-character secret and sets `.env` to mode `0600`.
- Redaction helper `security.redact()` exists for anything that must be logged.

## Audit logging

Every privileged action is written to `audit_log` with timestamp, actor, action
and detail: login success and failure, logout, link creation, revocation, restore
and deletion, campaign creation and archiving, retention purge, and each erasure
operation (all events, one link, one visitor).

## Error handling

`500` responses render a generic page. The exception is logged server side and
never shown to the client, because a traceback leaks configuration. A test
asserts that no traceback or framework banner appears on an error page.
